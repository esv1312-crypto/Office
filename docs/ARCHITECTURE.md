# AI-ОФИС — архитектура

## 1. Верхний уровень

AI-ОФИС
└── Project / Product
    ├── Interfaces
    │   ├── Native Mobile
    │   └── ChatGPT App
    ├── Backend
    ├── Data
    └── Operations

ОФИС находится над конкретным продуктом как управляющая и исполнительная организация.

## 2. Универсальность

Нельзя зашивать в ядро фиксированный список профессий.

Вместо этого используются:

- Role — функциональная роль;
- Competency — конкретная компетенция;
- Specialist — агент/исполнитель, обладающий набором компетенций;
- Team — временная или постоянная группа специалистов;
- Department — область деятельности;
- Room — рабочее пространство/контекст;
- Tool — подключаемый инструмент.

Новая предметная область должна добавляться декларативно, без переписывания ядра оркестратора.

Примеры областей:

- software engineering;
- UI/UX;
- product management;
- marketing;
- mathematics;
- law;
- construction;
- interior design;
- research;
- finance.

## 3. Жизненный цикл проекта

### INTAKE
Получение цели, ограничений, критериев результата и исходных материалов.

### RECON
Исследование проекта, репозитория, текущего состояния и зависимостей.

### PLAN
Построение адаптивного плана. План не считается навсегда заданным: он может изменяться по результатам выполнения.

### DELEGATE
Подбор компетенций и назначение подходящих специалистов/команд.

### EXECUTE
Выполнение задач инструментами в облачной рабочей среде.

### VERIFY
Независимая проверка результата против требований.

### FIX
Исправление обнаруженных проблем.

### RETEST
Повторная проверка после исправлений.

### EVIDENCE
Фиксация доказательств: commit, test result, build, artifact, log, report или иной проверяемый результат.

## 4. Исполнение

Project Runner связывает:

Chief → Plan → Tasks → Scheduler → Workers/Agents → Tools → Verification → FIX/RETEST → Evidence → State/Event Store.

Для долгих задач предусматриваются:

- heartbeat;
- watchdog;
- recovery/resume;
- идемпотентное выполнение;
- сохранение состояния;
- журнал событий.

## 5. Человек в контуре

ОФИС должен самостоятельно выполнять рутинную работу, но критические действия могут требовать human approval.

Approval должен быть отдельным состоянием процесса, а не сообщением, потерянным в чате.

Примеры:

- публикация;
- удаление данных;
- изменение production;
- финансовое действие;
- необратимое действие;
- выпуск продукта.

## 6. Интерфейс

Главный чат предназначен для:

- постановки задач;
- обсуждения;
- управления;
- согласования;
- отчётов;
- голосового взаимодействия.

Файлы и код не должны превращать главный чат в файловое хранилище.

Рабочие материалы живут в GitHub/Cloud и привязываются к проектам и задачам.
