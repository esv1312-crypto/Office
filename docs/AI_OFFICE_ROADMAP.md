# AI-ОФИС — дорожная карта автономного MVP

## Главная цель
INTAKE → RECON → PLAN → DELEGATE → EXECUTE → VERIFY → FIX → RETEST → EVIDENCE → DONE

Офис сам планирует, делегирует, выполняет разрешённые действия, проверяет результат, восстанавливается после ошибок и работает только с легальными бесплатными AI-ресурсами, пока не получено явное разрешение на платные.

## Приоритеты

### P0 — Multi-provider AI Gateway
**Сейчас.**
- Gemini — основной провайдер.
- OpenRouter и Cloudflare Workers AI — адаптеры.
- AI_FREE_ONLY=true блокирует платный OpenAI.
- Resource Manager отслеживает конфигурацию бесплатных провайдеров.
- Нужно: добавить легальные ключи, проверить реальный fallback при квоте/ошибке Gemini.
- В evidence фиксировать provider → failure → fallback → success.

**Готово, когда:** Gemini исчерпал квоту/сломался → офис сам использовал другой настроенный бесплатный провайдер → задача завершилась успешно.

### P1 — Browser Tool
**Следующий шаг.**
Браузер очень полезен: поиск официальной регистрации, документации, актуальных free-tier условий, моделей и страниц создания API keys; сбор ссылок/evidence.
- Только легальные действия.
- Не обходить CAPTCHA/авторизацию/ограничения.
- Не использовать чужие или утёкшие ключи.
- Browser — инструмент офиса, а не отдельный мозг.

**Готово, когда:** аналитик может исследовать провайдера через браузер и вернуть проверяемые источники.

### P2 — Реальные Tool Actions
**Частично готово.**
- Tool Registry + Policy.
- GitHub read/write.
- Следом: capability scopes, безопасные операции, evidence каждого действия.
- Произвольный shell пока не давать.

**Готово, когда:** worker реально меняет проект разрешённым инструментом, а результат можно проверить.

### P3 — Независимая Verification
**Реализована; нужен реальный тест.**
- отдельный Verifier;
- PASS/FAIL;
- evidence;
- DONE только после проверки.
- Тест: намеренная ошибка → FAIL; исправленный результат → PASS.

### P4 — Recovery + Replacement
**Реализована; нужен реальный end-to-end тест.**
- Failure Classifier;
- FIX/RETEST;
- bounded retry;
- replacement worker.
- Тест: worker падает → замена → исправление → повторная проверка → DONE.

### P5 — Live Monitor
**Работает; доводим после P0–P4.**
- задачи, сотрудники, ошибки, retries, fallback, recovery, evidence;
- показывать текущего AI-провайдера и причину fallback;
- считать уникальные активные задачи, а не события.

### P6 — Динамические специалисты и департаменты
Офис универсален: новые роли, компетенции, команды и комнаты добавляются без переписывания ядра.

### P7 — Knowledge/Evidence Layer
Накопление источников, решений, доказательств и истории. Сначала используем существующий GitHub/инфраструктуру; отдельную БД знаний добавляем только при необходимости.

### P8 — Дополнительные внешние инструменты
Подключаем только под конкретную задачу. GitHub/Render/Browser — ядро внешних инструментов. Не добавляем дублирующие task managers без необходимости.

### P9 — Дополнительные AI-провайдеры
После стабилизации fallback исследуем новые легальные бесплатные/условно-бесплатные варианты. Claude и OpenAI не блокируют текущий MVP.

## Почему Browser Tool важен
Браузер — не «поиск халявных ключей». Его правильная роль — **исследователь и оператор официальных сайтов**: найти условия, открыть регистрацию, проверить документацию, помочь пройти разрешённый процесс получения собственного ключа и сохранить evidence.

## Жёсткие правила
1. Только собственные/легально полученные credentials.
2. Никаких платных запросов без явного разрешения.
3. Адаптер ≠ реально доступный провайдер; доступность подтверждается запросом.
4. DONE только после независимой проверки.
5. UI не является доказательством; нужны events + tool results + verification evidence.
6. Код и артефакты — GitHub/облако, не главный голосовой чат.
7. Каждый приоритет проходит: код → deploy → реальный тест → evidence.

## Текущая траектория
P0 Multi-provider → P1 Browser → P2 Tools → P3 Verification → P4 Recovery → P5 Monitor → P6 Dynamic Office → P7 Knowledge → P8 Tools → P9 AI providers.

OpenAI остаётся отдельным будущим этапом и не включается автоматически в free-only режиме.
