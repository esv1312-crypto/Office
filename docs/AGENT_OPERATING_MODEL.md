# Agent Operating Model

## Chief of Staff

Chief of Staff — центральный оркестратор.

Он не обязан лично выполнять работу. Его задача:

1. понять цель;
2. определить необходимые компетенции;
3. создать или собрать команду;
4. сформировать план;
5. распределить задачи;
6. контролировать состояние;
7. запускать проверку;
8. организовывать исправления;
9. собирать evidence;
10. докладывать человеку.

## Dynamic Competency Pool

ОФИС хранит не только список агентов, а каталог компетенций.

Для каждой задачи подбирается минимально достаточный набор компетенций.

Если подходящего специалиста нет, система должна уметь создать/сконфигурировать нового специалиста на основе доступных моделей, инструкций, инструментов и требований роли.

## Departments and Rooms

Department — устойчивое направление деятельности.

Room — рабочий контекст конкретного проекта, задачи или направления.

Они создаются динамически.

Пример:

Project: новое мобильное приложение

Departments:
- Product
- Engineering
- Design
- QA

Rooms:
- Product Discovery
- Mobile Engineering
- Backend
- UI Design
- Release QA

Для другого проекта набор может быть совершенно другим.

## Workers

Worker — исполняющий агент, которому назначена конкретная задача.

Worker получает:

- task;
- acceptance criteria;
- relevant context;
- allowed tools;
- workspace;
- dependencies;
- expected evidence.

Worker не должен считать задачу выполненной только потому, что получил успешный ответ от инструмента.

## Verification

Verifier отделён от исполнителя.

Verifier получает исходные требования и результат и проверяет:

- функциональность;
- соответствие требованиям;
- отсутствие регрессий;
- тесты;
- артефакты;
- evidence.

При провале создаётся цикл FIX → RETEST.

## State

Каждый проект и task должны иметь машиночитаемое состояние.

Минимальные состояния задачи:

QUEUED
RUNNING
WAITING_APPROVAL
VERIFYING
FAILED
FIXING
RETESTING
DONE
BLOCKED

Состояние должно сохраняться вне чата.
