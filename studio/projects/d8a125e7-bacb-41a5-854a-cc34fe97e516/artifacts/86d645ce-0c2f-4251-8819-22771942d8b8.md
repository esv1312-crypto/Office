### Overview  
The **Self‑Development & Notebook System** is a lightweight, version‑controlled logging framework that records every decision, task, commit, PR, deployment, test run, QA verdict, blocker, and next action taken during studio development.  

* **NotebookManager** – a **ModuleScript** that defines the data model and provides a public API (`addRecord`, `getHistory`, `reset`) for any component to log information.  
* **NotebookLogger** – a **Server Script** that receives logged events via a **RemoteEvent** (`LogEvent`) and forwards them to `NotebookManager`. It validates that the caller is a trusted developer (developer‑ID passed in the payload).  
* **NotebookViewer** – a **LocalScript** that presents a simple UI (ScrollingFrame + TextLabels) allowing developers to read the current notebook content directly in‑studio.  

All components are **independently testable**: the ModuleScript can be unit‑tested with mock data, the Server Script can be tested by invoking `LogEvent` with fabricated payloads, and the UI can be verified manually.

## 1. ModuleScript – `NotebookManager`

```lua
-- ### File: ReplicatedStorage/Modules/NotebookManager (ModuleScript)
local NotebookManager = {}

-- Internal state (in‑memory). In a real workflow this would be persisted
-- to a file in the `studio-operations-notebook` branch via CI.
NotebookManager._records = {}   -- array of record tables

-- Record schema (for documentation)
-- {
--   id: string,                     -- unique UUID
--   timestamp: number,              -- os.time()
--   decision: string,               -- free‑form description
--   taskId: string,                 -- task/plan ID (e.g., "86d645ce-...")
--   commitSha: string,              -- git commit SHA
--   prLink: string,                 -- URL to PR
--   deploymentId: string,           -- Render/Deploy ID
--   testCommand: string,            -- command run (e.g., "lua test")
--   testExitCode: number,           -- 0 = success
--   qaVerdict: string,              -- "PASS", "FAIL", "BLOCKED", etc.
--   blockers: {string},             -- list of blocker descriptions
--   nextActions: {string},          -- list of next steps
-- }

function NotebookManager._generateId()
    return "nb_" .. tostring(os.time()) .. "_" .. math.random(1e6)
end

function NotebookManager.addRecord(payload)
    -- payload must be a table that conforms to the schema above.
    assert(type(payload) == "table", "Payload must be a table")
    local record = {
        id = NotebookManager._generateId(),
        timestamp = os.time(),
        decision = payload.decision or "",
        taskId = payload.taskId or "",
        commitSha = payload.commitSha or "",
        prLink = payload.prLink or "",
        deploymentId = payload.deploymentId or "",
        testCommand = payload.testCommand or "",
        testExitCode = payload.testExitCode or 0,
        qaVerdict = payload.qaVerdict or "",
        blockers = payload.blockers or {},
        nextActions = payload.nextActions or {},
    }
    table.insert(NotebookManager._records, record)
    return record.id
end

function NotebookManager.getHistory()
    -- Return a shallow copy so callers cannot mutate internal state.
    return table.clone(NotebookManager._records)
end

function NotebookManager.reset()
    NotebookManager._records = {}
end

return NotebookManager
```

*Key points*  
* The module lives in **ReplicatedStorage** so both server and client can require it.  
* All data is kept in memory; a CI pipeline would periodically dump the table to a file in the `studio-operations-notebook` branch (outside the scope of this worker).  
* The API is deliberately minimal to keep the system maintainable.

## 2. Server Script – `NotebookLogger`

```lua
-- ### File: ServerScriptService/NotebookLogger (Script)
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Players = game:GetService("Players")
local LogEvent = ReplicatedStorage:WaitForChild("LogEvent")   -- RemoteEvent

local NotebookManager = require(ReplicatedStorage.Modules.NotebookManager)

-- Mapping of developer UserId → allowed (trusted) status.
-- In a real studio this could be loaded from a config file.
local TRUSTED_DEVS = {
    [12345678] = true,   -- example developer ID
    [87654321] = true,
}

local function isTrusted(devId)
    return TRUSTED_DEVS[devId] == true
end

LogEvent.OnServerEvent:Connect(function(devId, payload)
    if not isTrusted(devId) then
        warn("NotebookLogger: untrusted developer attempted to log", devId)
        return
    end

    -- Validate payload shape (lightweight)
    if type(payload) ~= "table" then
        warn("NotebookLogger: malformed payload from", devId)
        return
    end
    -- Ensure required fields exist (optional – can be relaxed)
    if payload.taskId == nil then
        warn("NotebookLogger: missing taskId from", devId)
        return
    end

    -- Forward to the ModuleScript (runs on the server, but the ModuleScript
    -- is required from ReplicatedStorage, which is replicated to the server).
    NotebookManager.addRecord(payload)
end)

-- Optional: expose a RemoteFunction for read‑only history queries.
local GetHistory = Instance.new("RemoteFunction")
GetHistory.Name = "GetHistory"
GetHistory.Parent = ReplicatedStorage
GetHistory.OnServerInvoke = function(devId)
    if not isTrusted(devId) then
        warn("NotebookLogger: untrusted request for history", devId)
        return nil
    end
    return NotebookManager.getHistory()
end
```

*Key points*  
* Runs **only on the server**, guaranteeing that only trusted developers can modify the notebook.  
* Uses a **RemoteEvent** (`LogEvent`) for fire‑and‑forget logging and a **RemoteFunction** (`GetHistory`) for read‑only queries.  
* The trust check is simple; in production you could integrate with an authentication system.

## 3. LocalScript – `NotebookViewer`

```lua
-- ### File: StarterPlayerScripts/NotebookViewer (LocalScript)
local Players = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local player = Players.LocalPlayer

local function createViewer()
    local screenGui = Instance.new("ScreenGui")
    screenGui.Name = "NotebookViewer"
    screenGui.ResetOnSpawn = false
    screenGui.Parent = player:WaitForChild("PlayerGui")

    local scroll = Instance.new("ScrollingFrame")
    scroll.Name = "Scroll"
    scroll.Size = UDim2.new(1, 0, 1, 0)
    scroll.Position = UDim2.new(0, 0, 0, 0)
    scroll.BackgroundTransparency = 1
    scroll.CanvasSize = UDim2.new(0, 0, 0, 0)
    scroll.Parent = screenGui

    local function populate(records)
        scroll.CanvasSize = UDim2.new(0, 0, 0, 0)
        for _, rec in ipairs(records) do
            local label = Instance.new("TextLabel")
            label.Name = "Entry"
            label.Size = UDim2.new(1, 0, 0, 40)
            label.BackgroundTransparency = 0.8
            label.TextXAlignment = Enum.TextXAlignment.Left
            label.TextYAlignment = Enum.TextYAlignment.Top
            label.Font = Enum.Font.SourceSans
            label.TextSize = 14
            label.Text = string.format(
                "[%s] %s (Task: %s) | Commit: %s | PR: %s | Deploy: %s | Test: %s (code %d) | QA: %s | Blockers: %s | Next: %s",
                os.date("%Y-%m-%d %H:%M:%S", rec.timestamp),
                rec.decision or " — ",
                rec.taskId or " — ",
                rec.commitSha or " — ",
                rec.prLink or " — ",
                rec.deploymentId or " — ",
                rec.testCommand or " — ",
                rec.testExitCode,
                rec.qaVerdict or " — ",
                table.concat(rec.blockers, "; ") or " — ",
                table.concat(rec.nextActions, "; ") or " — "
            )
            label.Parent = scroll
            scroll.CanvasSize = UDim2.new(0, 0, 0, (scroll.CanvasSize.Y.Scale + 0.04) * 1000) -- rough scaling
        end
    end

    -- Request history from the server
    local getHist = ReplicatedStorage:WaitForChild("GetHistory")
    local success, history = pcall(function() return getHist:InvokeServer() end)
    if success then
        populate(history)
    else
        warn("Failed to load notebook history:", history)
    end
end

createViewer()
```

*Key points*  
* The UI is **purely client‑side**; it never writes to the notebook, only reads via `GetHistory`.  
* The scrolling frame automatically expands to show all entries.  
* The text format is deterministic and human‑readable, satisfying the “queryable history” requirement.

## 4. Deterministic Studio Build Script (Visual/World)

The following script creates a tiny test world that demonstrates the notebook UI in‑studio. It can be run from **Studio → View → Scripts → New LocalScript** (placed in `StarterPlayerScripts`). The script **does not** perform any actual Studio execution; it merely defines the objects.

```lua
-- ### File: StarterGui/BuildTestWorld (Script)  -- *Deterministic build script*
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Players = game:GetService("Players")

-- 1. Create a ScreenGui container
local screenGui = Instance.new("ScreenGui")
screenGui.Name = "TestGui"
screenGui.Parent = game.Players.LocalPlayer:WaitForChild("PlayerGui")

-- 2. Create a Frame that will host the notebook viewer
local frame = Instance.new("Frame")
frame.Name = "NotebookFrame"
frame.Size = UDim2.new(0.6, 0, 0.8, 0)   -- 60% width, 80% height
frame.Position = UDim2.new(0.2, 0, 0.1, 0) -- centered horizontally, top‑ish
frame.BackgroundTransparency = 0.5
frame.BackgroundColor3 = Color3.fromRGB(30, 30, 30)
frame.Parent = screenGui

-- 3. Add a close button
local closeBtn = Instance.new("TextButton")
closeBtn.Name = "CloseBtn"
closeBtn.Size = UDim2.new(0, 80, 0, 30)
closeBtn.Position = UDim2.new(1, -90, 0, 5)
closeBtn.BackgroundColor3 = Color3.fromRGB(80, 80, 80)
closeBtn.TextColor3 = Color3.fromRGB(255, 255, 255)
closeBtn.Font = Enum.Font.SourceSansBold
closeBtn.TextSize = 14
closeBtn.Text = "Close"
closeBtn.Parent = frame

closeBtn.MouseButton1Click:Connect(function()
    screenGui:Destroy()
end)

-- 4. Load the NotebookViewer LocalScript (the one defined above)
local viewerScript = Instance.new("LocalScript")
viewerScript.Name = "NotebookViewer"
viewerScript.Source = "rbxassetid://0"   -- placeholder; in real use you would require the script asset
viewerScript.Parent = frame

print("Test world built – open the NotebookViewer UI to see the history.")
```

### Manual Studio Verification Checklist  

1. **Open Studio** and run the game (Play).  
2. Verify that a **ScreenGui** named `TestGui` appears with a dark gray `NotebookFrame`.  
3. Click the **Close** button – the UI should disappear.  
4. Re‑open the game; the UI should re‑appear (the script recreates it each time).  
5. In the **Output** window, confirm the print statement “Test world built …”.  

*If any step fails, adjust the `Size`/`Position` values or ensure the `LocalScript` is correctly parented.*

The **master notebook** lives on the `studio-operations-notebook` branch. Every time a developer runs a task, merges a PR, or triggers a deployment, the corresponding `LogEvent` payload is sent to `NotebookLogger`, which updates the in‑memory table. A CI job would then commit the updated `NotebookManager` ModuleScript (or a generated `.md` file) to that branch, ensuring the notebook is always in sync with the repository.

| Criterion | Evidence (to be included in the PR) |
