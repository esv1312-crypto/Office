# Product Profile & Skill Extensibility Framework — Architecture & Implementation

## 1. Design goals and constraints

The framework must satisfy four acceptance criteria:

1. **Profiles as data** — Roblox, web, mobile, AI product, automation, design, marketing are registrable as plain data tables declaring skills and tool requirements.
2. **Zero core modification** — registering a new profile must not touch core workflow code.
3. **Domain-agnostic core** — core modules contain no Roblox-specific or single-domain branching logic.
4. **Persisted, validated selection** — per-project profile selection is persisted and validated against the registered set.

The core insight: **the registry is a generic key→value store over validated profile data**. Nothing in the core knows what "Roblox" or "web" means. Concrete profiles live in separate data modules; a single composition point wires them into the registry. Persistence is backend-injected so the core never depends on a specific storage technology.

## 2. Module layout (proposed)

```
ReplicatedStorage/ProductProfiles/
  Registry.lua              -- CORE: generic profile registry (domain-agnostic)
  ProfileValidator.lua      -- CORE: structural validation of profiles/skills/tools
  ProjectProfileStore.lua   -- CORE: persisted per-project selection + validation
  BuiltinProfiles.lua       -- COMPOSITION: registers the 7 built-in profiles
  profiles/
    Roblox.lua              -- DATA
    Web.lua                 -- DATA
    Mobile.lua              -- DATA
    AIProduct.lua           -- DATA
    Automation.lua          -- DATA
    Design.lua              -- DATA
    Marketing.lua           -- DATA
  README.md                 -- usage + extension guide
```

**Boundary rule:** `Registry`, `ProfileValidator`, `ProjectProfileStore` are the *core* and must never reference a specific profile id, domain, or Roblox API. `BuiltinProfiles.lua` is the *only* place that references concrete profiles and the only place that uses Roblox module-loading (`require`/`script.Parent`). Adding a discipline = add one data module + one `require` line in `BuiltinProfiles.lua`. Core code is untouched.

## 3. Data model

```
Profile = {
  id: string,            -- unique slug, e.g. "roblox"
  name: string,          -- display name
  description: string,
  domain: string?,       -- optional classification tag
  version: string?,
  skills: [ { id, name, description? } ],
  toolRequirements: [ { id, name?, required? } ]
}
```

--!strict
-- Registry.lua
-- CORE: Generic, domain-agnostic registry for product profiles.
-- Contains NO Roblox-specific or single-domain branching logic.

local Registry = {}
Registry.__index = Registry

local function validateProfile(profile)
	if type(profile) ~= "table" then
		return false, "profile must be a table"
	end
	if type(profile.id) ~= "string" or #profile.id == 0 then
		return false, "profile.id must be a non-empty string"
	end
	if type(profile.name) ~= "string" or #profile.name == 0 then
		return false, "profile.name must be a non-empty string"
	end
	if profile.skills ~= nil and type(profile.skills) ~= "table" then
		return false, "profile.skills must be a table when present"
	end
	if profile.toolRequirements ~= nil and type(profile.toolRequirements) ~= "table" then
		return false, "profile.toolRequirements must be a table when present"
	end
	return true, nil
end

function Registry.new(options)
	options = options or {}
	local self = setmetatable({}, Registry)
	self._profiles = {}
	self._allowOverwrite = options.allowOverwrite or false
	return self
end

-- Register a profile. Returns ok, err.
function Registry:register(profile)
	local ok, err = validateProfile(profile)
	if not ok then
		return false, err
	end
	if self._profiles[profile.id] and not self._allowOverwrite then
		return false, string.format("profile already registered: %s", profile.id)
	end
	self._profiles[profile.id] = profile
	return true, nil
end

-- Get a profile by id. Returns profile or nil.
function Registry:get(id)
	return self._profiles[id]
end

-- Check whether a profile id is registered.
function Registry:has(id)
	return self._profiles[id] ~= nil
end

-- List all registered profile ids (sorted).
function Registry:list()
	local ids = {}
	for id in pairs(self._profiles) do
		table.insert(ids, id)
	end
	table.sort(ids)
	return ids
end

-- Resolve a selection string against registered profiles.
-- Returns profile, nil on success; nil, err on failure.
function Registry:resolve(selection)
	if type(selection) ~= "string" then
		return nil, "selection must be a profile id string"
	end
	local profile = self._profiles[selection]
	if not profile then
		return nil, string.format("unknown profile: %s", selection)
	end
	return profile, nil
end

return Registry
```

--!strict
-- ProfileValidator.lua
-- CORE: Structural validation of profile skills and tool requirements.
-- Domain-agnostic; no product-specific logic.

local ProfileValidator = {}

local function validateSkill(skill)
	if type(skill) ~= "table" then
		return false, "skill must be a table"
	end
	if type(skill.id) ~= "string" or #skill.id == 0 then
		return false, "skill.id must be a non-empty string"
	end
	if type(skill.name) ~= "string" or #skill.name == 0 then
		return false, "skill.name must be a non-empty string"
	end
	if skill.description ~= nil and type(skill.description) ~= "string" then
		return false, "skill.description must be a string when present"
	end
	return true, nil
end

local function validateTool(tool)
	if type(tool) ~= "table" then
		return false, "tool must be a table"
	end
	if type(tool.id) ~= "string" or #tool.id == 0 then
		return false, "tool.id must be a non-empty string"
	end
	if tool.required ~= nil and type(tool.required) ~= "boolean" then
		return false, "tool.required must be a boolean when present"
	end
	return true, nil
end

-- Validate the full profile structure. Returns ok, err.
function ProfileValidator.validate(profile)
	if type(profile) ~= "table" then
		return false, "profile must be a table"
	end

	if profile.skills ~= nil then
		if type(profile.skills) ~= "table" then
			return false, "profile.skills must be a table"
		end
		for i, skill in ipairs(profile.skills) do
			local ok, err = validateSkill(skill)
			if not ok then
				return false, string.format("profile.skills[%d]: %s", i, err)
			end
		end
	end

	if profile.toolRequirements ~= nil then
		if type(profile.toolRequirements) ~= "table" then
			return false, "profile.toolRequirements must be a table"
		end
		for i, tool in ipairs(profile.toolRequirements) do
			local ok, err = validateTool(tool)
			if not ok then
				return false, string.format("profile.toolRequirements[%d]: %s", i, err)
			end
		end
	end

	return true, nil
end

return ProfileValidator
```

### File: ReplicatedStorage/ProductProfiles/ProjectProfileStore.lua

```lua
--!strict
-- ProjectProfileStore.lua
-- CORE: Persists the selected product profile per project and validates the
-- selection against the registered profiles. The persistence backend is
-- injected, so this module is storage-agnostic and domain-agnostic.

local ProjectProfileStore = {}
ProjectProfileStore.__index = ProjectProfileStore

-- backend contract:
--   backend:set(projectId, profileId) -> ok, err
--   backend:get(projectId)           -> storedId | nil, err
function ProjectProfileStore.new(registry, backend)
	if type(registry) ~= "table" then
		error("ProjectProfileStore.new: registry is required", 2)
	end
	if type(backend) ~= "table" then
		error("ProjectProfileStore.new: backend is required", 2)
	end
	local self = setmetatable({}, ProjectProfileStore)
	self._registry = registry
	self._backend = backend
	return self
end

-- Select a profile for a project. Validates against the registry before persisting.
-- Returns ok, err.
function ProjectProfileStore:select(projectId, profileId)
	if type(projectId) ~= "string" or #projectId == 0 then
		return false, "projectId must be a non-empty string"
	end
	local profile, err = self._registry:resolve(profileId)
	if not profile then
		return false, err
	end
	local ok, backendErr = self._backend:set(projectId, profileId)
	if not ok then
		return false, backendErr or "failed to persist profile selection"
	end
	return true, nil
end

-- Get the currently selected profile for a project.
-- Returns profile, nil on success; nil, err on failure (nil, nil if unset).
function ProjectProfileStore:get(projectId)
	if type(projectId) ~= "string" or #projectId == 0 then
		return nil, "projectId must be a non-empty string"
	end
	local storedId, err = self._backend:get(projectId)
	if err then
		return nil, err
	end
	if storedId == nil then
		return nil, nil
	end
	local profile, resolveErr = self._registry:resolve(storedId)
	if not profile then
		return nil, resolveErr
	end
	return profile, nil
end

return ProjectProfileStore
```

```lua
--!strict
-- BuiltinProfiles.lua
-- COMPOSITION: Registers the built-in product profiles into a registry.
-- This is the ONLY module that references concrete profiles and the only
-- place that uses Roblox module-loading. The core Registry remains
-- domain-agnostic and is never modified to add a discipline.

local Registry = require(script.Parent.Registry)
local ProfileValidator = require(script.Parent.ProfileValidator)

local registry = Registry.new()

local profileModules = {
	require(script.Parent.profiles.Roblox),
	require(script.Parent.profiles.Web),
	require(script.Parent.profiles.Mobile),
	require(script.Parent.profiles.AIProduct),
	require(script.Parent.profiles.Automation),
	require(script.Parent.profiles.Design),
	require(script.Parent.profiles.Marketing),
}

for _, profile in ipairs(profileModules) do
	local ok, err = ProfileValidator.validate(profile)
	if not ok then
		error("BuiltinProfiles: invalid profile: " .. tostring(err))
	end
	local registered, regErr = registry:register(profile)
	if not registered then
		error("BuiltinProfiles: failed to register profile: " .. tostring(regErr))
	end
end

return registry
```

## 5. Extension mechanism (adding a future discipline)

1. Create `profiles/NewDiscipline.lua` returning a profile data table (same schema).
2. Add one `require(script.Parent.profiles.NewDiscipline)` line to `BuiltinProfiles.lua`.
3. Done — no core module changes.

The core `Registry`, `ProfileValidator`, and `ProjectProfileStore` are never edited to add a discipline. This satisfies **AC2**.

## 6. Persistence backend example (injected, not core)

`ProjectProfileStore` takes any backend implementing `set(projectId, profileId)` and `get(projectId)`. A Roblox DataStore backend is one option, but the core does not depend on it:

```lua
-- Example backend (not part of core; lives in the host application)
local DataStoreService = game:GetService("DataStoreService")
local store = DataStoreService:GetDataStore("ProjectProfiles")

local Backend = {}
function Backend.set(projectId, profileId)
	local ok, err = pcall(function()
		store:SetAsync(projectId, profileId)
	end)
	return ok, err
end
function Backend.get(projectId)
	local ok, value = pcall(function()
		return store:GetAsync(projectId)
	end)
	if not ok then
		return nil, value
	end
	return value, nil
end
return Backend
```

## 7. Acceptance criteria mapping

| Criterion | How it is satisfied |
|---|---|
| **AC1** — listed profiles registrable as data with skills + tool requirements | Each of the 7 profiles is a plain data table with `skills` and `toolRequirements`; `BuiltinProfiles` registers them all. |
| **AC2** — new profile requires no core modification | Core modules are generic; adding a discipline = new data module + one `require` line in the composition point. |
| **AC3** — core has no Roblox-specific/single-domain branching | `Registry`, `ProfileValidator`, `ProjectProfileStore` contain no profile-id, domain, or Roblox API references. Only the composition module and data modules are domain-specific. |
| **AC4** — selection persisted per project and validated | `ProjectProfileStore:select` resolves against the registry before persisting; `get` re-validates stored ids against registered profiles. |
